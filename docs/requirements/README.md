# 项目目标与示例规则

- 适用范围：greeting Go / Kratos 模板
- 维护责任：项目与业务模块维护者
- 核对日期：2026-10-13

## 目标与范围

本项目演示从明确接口、业务规则、存储语义和失败行为出发，分层实现并验证业务。默认只启用 HTTP/gRPC，可选 WebSocket、MQTT、RabbitMQ、TCP、UDP 和 KCP；应用运行不依赖 AI 平台。

开发者可以按 domain 扩展自己的业务。可选数据库、发现、远程客户端、日志、指标和追踪提供接入能力，不能据此推断业务已具备持久化、事务、幂等或生产部署保障。

## 问候规则与验收

- 创建时去除名称首尾空白，合法名称生成问候及记录 ID；再按该 ID 查询同一条记录。
- 非法名称或 ID 返回参数错误，不存在的记录返回缺失错误；具体字段、范围、序列化和错误见 [问候契约](../interfaces/README.md#问候接口)。
- 当前 GET 创建路由是兼容示例，新增业务创建资源使用 POST，保留已发布契约兼容性。
- 本地内存、远程转发与可选事件的实际语义见 [存储边界](../architecture/README.md#存储与演进)，测试、构建与目标环境验收分别记录。

新增功能证明成功、失败和边界行为，新入口证明真实请求到仓储链路。长期需求留在本页，复杂任务的范围、进度和结果留在 [计划](../plans/README.md)；不为示例编造产品路线图、容量或恢复承诺。
