## 目标与范围

- 修复 GitHub 推送回执提示的依赖告警，依据当前官方漏洞数据核对受影响版本，升级到兼容的修复版本并验证模板能力。
- 包含 go.mod/go.sum、必要的兼容适配及 Go/CI/镜像版本和扫描入口；保留默认关闭外部依赖、既有协议、存储与清理语义。
- 不以删除可选功能、忽略告警、关闭检测或放宽测试代替修复，不访问生产服务或修改本机敏感配置。

## 规则与现有链路

- 责任入口为 go.mod/go.sum；使用者包括 internal/server、internal/pkg 的数据库/发现/远程客户端/指标/追踪等适配器，server → service → biz → data 业务链路保持原职责。
- 公共 HTTP/gRPC、消息、配置、内存/远程和事件失败语义沿 [架构](../architecture/README.md) 与 [接口](../interfaces/README.md)；必要代码适配留在原能力所有者。
- 模块级扫描检查选定依赖版本，调用级扫描检查当前构建与测试可达路径；两者与 GitHub 告警状态分别记录，不用扫描进程的 JSON 退出码代替漏洞数量。
- 验收沿 [开发验证选择](../development/README.md#验证选择)；生成依赖和协议相关变化补齐其真实链路验证。
